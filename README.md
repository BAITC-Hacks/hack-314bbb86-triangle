# Triangle — «Аким на 5 часов»

Hackathon team repository for Triangle. Трек 12, Astana Innovations.

Учебный AI-симулятор управления городом: 100 условных единиц, пять решений,
пять районов и измеримые последствия через восемь кварталов.
Пользователь выбирает мероприятия и районы, а модель рассчитывает
**Astana Quality of Life Score**. AI получает готовые факты и объясняет их.

## Быстрый запуск

Нужен **Node.js 22.12 или новее**. Внешних пакетов нет: `npm install` не требуется.

```bash
git clone https://github.com/BAITC-Hacks/hack-314bbb86-triangle.git
cd hack-314bbb86-triangle
npm start
```

Откройте **http://127.0.0.1:3000**. В PowerShell при запрете выполнения `npm.ps1`
используйте `npm.cmd start`. Для перезапуска при изменении серверных файлов:
`npm run dev`. После изменения интерфейса обновите вкладку браузера.

## Подключение настоящего AI

Создайте локальный `.env` по образцу `.env.example`:

```dotenv
PORT=3000
HOST=127.0.0.1
OPENAI_API_KEY=ваш_ключ_OpenAI_API
OPENAI_MODEL=gpt-4.1-mini
```

Затем перезапустите сервер. Ключ вводится только в локальный `.env` или
в секреты серверного хостинга; этот файл исключён из Git. Ключ не отправляется
в браузер. Модель можно изменить на доступную вашему API-проекту модель,
поддерживающую Responses API и JSON Schema.

Интеграция использует [OpenAI Responses API](https://developers.openai.com/api/docs/guides/text)
через серверный `fetch`, `store: false` и структурированный JSON-ответ.
В запрос входят только синтетические данные и выбранные городские меры.
LLM не участвует в вычислении числового результата. Он объясняет сильные
стороны, риски, лаги, синергии и варианты улучшения, рассчитанные движком.

**Без API-ключа** весь симулятор работает, но объяснение формирует локальный
аналитический модуль. Это явно подписано «AI-ключ не настроен» и не выдаётся
за AI-анализ. При ошибке/таймауте провайдера используется тот же честный fallback.
Для демонстрации обязательного LLM-пункта жюри настройте API-ключ заранее.
Живой вызов OpenAI API проверен 23 сентября 2026: модель `gpt-4.1-mini`
вернула структурированный анализ демонстрационного сценария. Ключ настроен
только локально; каждому серверу/участнику нужен собственный `.env`.

## Демонстрация за 2 минуты

1. Нажмите «Загрузить пример». Выбраны школа, поликлиника и Safe City в Нуре,
   городская платформа обращений и чистое топливо в Сарыарке.
2. Стоимость — **95**, остаток — **5**. Нажмите «Рассчитать и получить анализ».
3. Score — **56,54307**, рост к базе **3,98539**, критических показателей — **0**.
   Работает синергия Safe City и платформы обращений.
4. Изучите риски и вклад мер. Сохраните сценарий «Приоритет — Нура».
5. Примените первую рекомендацию: заменить чистое топливо в Сарыарке на ЛРТ
   в Нуре. Новый бюджет — **100**, Score — **57,20556**. Пересчитайте и сохраните
   второй вариант для сравнения.
6. Сбросьте сценарий и выберите автобусные полосы. ЛРТ станет недоступным
   с объяснением конфликта. При четырёх решениях итоговый анализ недоступен.

## Правила и формула

Подробный датасет организаторов — источник правил и всех исходных значений.
В описании задачи можно прочитать требование как «по одной мере из пяти
направлений», но подробные правила и пример допускают две социальные меры и
отсутствие транспорта. Реализовано **ровно 5 мер, максимум 2 из одного
направления**, то есть минимум 3 направления. Все 5 направлений доступны.

- Общий бюджет — 100, неиспользованный остаток не даёт бонуса.
- Ровно 5 решений; каждое мероприятие можно выбрать один раз.
- Районные меры требуют одного из пяти районов; городские не принимают район.
- Не больше двух мер одного направления.
- M1 и M3 несовместимы в любом районе.
- M4 + M7 и M5 + M13 несовместимы только в одном районе.
- Синергии: M1 + M2 → T1 +2 в районе M1; M10 + M12 → B1 +2 в районе M10;
  M5 + M6 → E2 +2 в районе M5. Синергии не масштабируются лагом.

```text
I'[район, показатель] = clip(I + Σ(эффект × (8 − лаг) / 8) + синергии, 0, 100)
D[район] = Σ(вес показателя × I')
D_avg = Σ(доля населения × D[район])
Score = 0.7 × D_avg + 0.3 × min(D) − N_crit
N_crit = число пар «район × показатель», у которых I' строго меньше 40
```

Веса: T1 .10, T2 .10, E1 .09, E2 .11, S1 .11, S2 .11, B1 .09, B2 .09,
C1 .10, C2 .10. Округление применяется только при отображении.
База: D_avg = 56,8624; min(D) = 49,18; N_crit = 2;
**Score = 52,55768**, на экране 52,56.

Пока не выбраны все пять мер, справа показывается только подписанный
промежуточный прогноз. Серверный итог для невалидного набора всегда `score: null`
и содержит причины отказа.

Вклад мероприятия — разница между итогом и расчётом без этой меры (leave-one-out).
Такие вклады нельзя складывать: пороги, минимум и синергии нелинейны.
Рекомендатель перебирает допустимые замены одной меры, включая смену района,
и показывает три лучших улучшения. Это локальный поиск, не доказательство
глобального оптимума.

## Что реализовано

- Интерактивная условная схема районов, режимы «Сейчас» / «Прогноз».
- 14 инициатив по пяти направлениям с ценой, лагом, эффектами и выбором района.
- Контроль бюджета, лимитов и конфликтов в интерфейсе и повторно на сервере.
- Точный Score, критические показатели, синергии, вклад каждого решения.
- Серверный AI-советник с явным локальным режимом при отсутствии подключения.
- Проверенные рекомендации, которые можно применить одной кнопкой.
- До восьми сценариев в localStorage с пересчётом результатов при загрузке.
- Сравнение сценариев, экспорт полного отчёта в JSON, печатная версия / PDF.
- Адаптивная вёрстка, клавиатурный выбор районов и видимый фокус.

## API

`GET /api/config` — версия модели, бюджет, горизонт, признак AI-подключения.

`POST /api/simulate` — проверка и итоговый расчёт.
`POST /api/analyze` — тот же серверный расчёт, рекомендации и отчёт.
Тело обоих POST:

```json
{"decisions":[{"measureId":"M7","districtId":"nura"},{"measureId":"M8","districtId":"nura"},{"measureId":"M10","districtId":"nura"},{"measureId":"M12"},{"measureId":"M5","districtId":"saryarka"}]}
```

Успех — 200, нарушение правил / неверный JSON — 400, тело больше 16 КиБ — 413,
неверный Content-Type — 415, превышение частоты AI-запросов — 429.
Числа, переданные клиентом отдельно от решений, не используются.
AI ограничен пятью запросами в минуту на адрес и тремя одновременными запросами;
таймаут провайдера — 25 секунд. Сервер по умолчанию слушает только loopback.


21 тест: точная база и пример, бюджет 100, превышение, лаги, все синергии и

Ручной smoke-тест: загрузить пример → рассчитать → сохранить → применить
улучшение → повторно рассчитать → проверить 57,21 и бюджет 100.

Работайте в отдельных ветках и объединяйте изменения через Pull Request.
GitHub хранит исходники; сохранять файл на своём компьютере недостаточно —
изменения становятся общими после commit/push. Общая таблица команд и аккаунты
пользователей не реализованы: сохранённые сценарии принадлежат текущему браузеру.

## Размещение и границы модели

Для демонстрации на сервере задайте `HOST=0.0.0.0`, `PORT` и секретный API-ключ
в окружении хостинга, запускайте `npm start`. Нужен Node-сервер: GitHub Pages
не запускает серверный AI. Публичный хостинг в рамках этой реализации не развёрнут.
Перед общедоступным платным AI добавьте аутентификацию, устойчивые лимиты и HTTPS:
текущий вариант предназначен для локальной/контролируемой хакатон-демонстрации.

Границы районов на схеме условные. Исходные числа синтетические, персональных
данных нет. Модель не учитывает инфляцию, миграцию, детальное землепользование,
коррупцию или реальные сроки стройки. Неожиданные события и автоматическая
генерация презентации не включены; отчёт можно распечатать в PDF.

Дальнейшее развитие: калибровка на открытых агрегированных городских данных,
сценарии неопределённости, общий рейтинг команд, более широкий поиск решений,
оценка фактической эффективности уже реализованных проектов.
